# energy-rss · 能源电力 RSS 订阅中心

把国家能源局、南方电网、北极星电力网、中国电机工程学报、电网技术这几家
「没有 RSS / RSS 被墙 / RSS 被反爬拦住」的站点, 变成 Inoreader 能稳定订阅的标准 RSS。

抓取跑在 GitHub Actions 上, 成品放在 GitHub Pages 上。你不需要服务器, 不需要买域名,
也不需要一直开着电脑。

---

## 一、你会拿到什么

总共 10 个源, 分成四组:

| 分组 | 源 | 说明 |
| --- | --- | --- |
| 国家能源局 | 通知 / 公告 / 能源要闻 | 通知和公告是政策原文入口, 能源要闻自带摘要 |
| 学术期刊 | 中国电机工程学报 / 电网技术 | 知网 RSS 重新封装, 含标题、作者、摘要 |
| 南方电网 | 公司要闻 / 一线传真 / 媒体关注 | 官网口径, 可替代公众号「南网50Hz」 |
| 北极星电力网 | 输配电 / 综合要闻 | 行业雷达, 条目多、更新快 |

每个源最终就是一个文件:

```
https://你的用户名.github.io/energy-rss/feeds/<源id>.xml
```

例如 `https://zhangsan.github.io/energy-rss/feeds/nea-tongzhi.xml`。

另外还会自动生成两个方便你的东西:

- `subscribe.opml` —— 在 Inoreader 里一次性导入全部源。
- `index.html` —— 一张网页, 每个源旁边有「在 Inoreader 订阅」按钮, 点一下直接加。

## 二、它到底解决了什么问题

这几家站点的情况和你手上那份清单说的不完全一样, 下面是我逐个实测的结果:

| 站点 | 官方 RSS | 实测结论 |
| --- | --- | --- |
| 国家能源局 | 无 | 列表页是 JS 渲染的, 抓 HTML 只能拿到空列表。但页面里藏着公开的 JSON 数据源, 能稳定取到通知/公告/要闻, 带发布时间和摘要 |
| 中国电机工程学报 | 知网 RSS | **RSS 本身完全正常, 而且当天就在更新**。Inoreader 报错不是格式问题, 是它的抓取服务器被知网拦了 |
| 电网技术 | 知网 RSS | 同上。另外 `www.dwjs.com.cn` 这个官网域名**已经解析不出来了**, 那个入口是废的, 别再试 |
| 南方电网报 / 南网50Hz | 无 | 官网新闻中心是静态页, 可以稳定抓。公众号那条路走 WeRSS 会一直不稳定, 不如直接用官网 |
| 北极星电力网 | 无 | 首页和多数频道页可以抓; 但 `news.bjx.com.cn` 挂了阿里云 WAF, 直接抓它的频道页会返回验证码 |

所以本方案的核心思路是: **凡是抓得到的, 我自己抓一遍, 重新封装成干净的标准 RSS,
再让 Inoreader 来拉我的链接**。这样它就不用去碰那些会拦它的服务器了。

## 三、部署（推荐路线, 大约五分钟）

你需要一个 GitHub 账号。免费账号足够, 仓库要选 Public
（免费账号的 Pages 只对公开仓库开放; 内容都是公开新闻, 没有隐私问题）。

### 第 1 步: 建一个空仓库

1. 浏览器打开 <https://github.com/new>
2. Repository name 填 `energy-rss`
3. 选 **Public**
4. **不要**勾 Add a README file
5. 点 Create repository, 然后复制页面给你的仓库地址备用

### 第 2 步: 把文件推上去

在 `energy-rss` 文件夹里双击 **`push-to-github.bat`**,
把刚才复制的仓库地址粘进去回车, 剩下的它全做完。

如果你更想手动来, 等价命令是:

```
cd 这个文件夹
git init -b main
git add .
git commit -m "初始化 energy-rss 订阅源"
git remote add origin https://github.com/你的用户名/energy-rss.git
git push -u origin main
```

第一次推送时弹出的登录窗口按提示登录 GitHub 就行。

### 第 3 步: 给 Actions 开写权限（不做这步, 定时更新会失败）

仓库页面 → **Settings** → 左侧 **Actions** → **General** →
拉到最下面 **Workflow permissions** → 选 **Read and write permissions** → Save。

### 第 4 步: 开启 GitHub Pages

仓库页面 → **Settings** → 左侧 **Pages** →
Source 选 **Deploy from a branch**, Branch 选 **main**, 目录选 **/docs** → Save。

### 第 5 步: 手动跑一次

仓库页面 → **Actions** 标签 → 左侧点 **更新 RSS 源** → 右侧 **Run workflow** → 绿色按钮。

等大约一分钟, 它会自己抓完十个源、生成文件并提交回仓库。

### 第 6 步: 确认地址

打开 `https://你的用户名.github.io/energy-rss/`。

看到那张订阅中心页面就成功了。每张卡片下面就是可以直接订阅的 XML 地址。

> 之后每 2 小时会自动跑一次。只有内容真的变了才会产生新提交, 仓库不会被日志淹没。

## 四、备用路线: 全程在网页上点（不想装 git 的话）

1. 按上面第 1 步建好空仓库。
2. 在仓库页面点 **Add file → Upload files**, 把 `build.py`、`sources.py`、
   `README.md`、`run_local.bat` 拖进去, 提交。
3. 再点 **Add file → Create new file**, 文件名直接输入
   `.github/workflows/update-feeds.yml`, 把工作流文件的内容粘进去, 提交。
4. 继续按上面的第 3、4、5 步操作。

网页上传有个坑: 隐藏目录 `.github` 用拖拽容易被浏览器跳过, 所以这一步要手动建文件。

## 五、把源加进 Inoreader

### 方式 A: 一次性全加（最省事）

1. 打开 `https://你的用户名.github.io/energy-rss/subscribe.opml` 下载文件。
2. Inoreader 里进 **设置（齿轮图标）→ 导入 → 从文件**, 选这个 opml。
3. 十个源一次性就进去了, 默认不会给你全部标记成未读。

### 方式 B: 一个一个点

打开订阅中心页面, 找到你要的源, 点卡片上的 **在 Inoreader 订阅** 按钮,
它会跳到 Inoreader 并自动填好地址。

### 方式 C: 手动粘贴地址

Inoreader → 左侧 **+ 添加订阅** → 把 `.../feeds/nea-tongzhi.xml` 这样的地址粘进去。

**建议的阅读顺序**: 先看「国家能源局」的两个源抓政策, 再看「南方电网」和期刊目录,
「北极星 · 综合要闻」条目多, 建议放到一个单独的文件夹, 有空再扫。

## 六、如果 GitHub 那边抓不到（保底方案）

GitHub Actions 的机器在国外。极少数情况下, 国内站点可能只放行国内 IP,
那第一跑就会看到某些源报「请求失败」。

判断方法: 看 Actions 的日志, 或者直接打开
`https://你的用户名.github.io/energy-rss/feeds/nea-tongzhi.xml` —— 如果是空的或 404,
说明这个源在 GitHub 上没抓到。

更省事的办法: 订阅中心页面上每个源下面都有一行状态, 写着「最新一条 某日某时 · 多少条」。
如果某个源一直是「还没有抓到内容」, 或者下面多出一条橙色报错, 那就是它在这台机器上抓不动。

这时候用本地方案, 让抓取在你的机器上跑（走的自然是你家的网络）:

1. 双击 **`run_local.bat`**, 它会抓一遍并生成 `docs\` 目录。
2. 确认没问题后, 双击 `push-to-github.bat`（或者手动 `git add . && git commit -m 更新 && git push`）把新生成的
   `docs\` 推上去。

想让它自动跑, 用 Windows 自带的「任务计划程序」:

1. Win 键搜「任务计划程序」→ 创建基本任务。
2. 触发器选「每天」, 或者「一次」然后设置重复间隔为 2 小时。
3. 操作选「启动程序」, 程序填 `run_local.bat` 的完整路径。
4. 起始于填这个文件夹的完整路径。

注意: 本地方案要求电脑当时是开着的。

## 七、加源、删源、改频率

想增删源只改 **`sources.py`** 一个文件。比如加一个北极星储能频道:

```python
{
    "id": "bjx-chuneng",
    "group": "北极星电力网",
    "title": "北极星 · 储能",
    "kind": "bjx",
    "page": "https://chuneng.bjx.com.cn/",
    "site": "https://chuneng.bjx.com.cn/",
    "desc": "储能频道最新资讯。",
},
```

改完推上去, 下一次 Actions 就会多生成一个 `feeds/bjx-chuneng.xml`。

几个经验:

- 北极星大部分频道页都能用 `kind="bjx"` 直接加, 但别用 `news.bjx.com.cn` 下面的路径, 会撞 WAF。
- 想改抓取频率, 改 `.github/workflows/update-feeds.yml` 里的 `cron` 那行。
  每 15 分钟一次差不多是免费额度的合理上限, 不建议更密。
- 想临时只测一个源, 本地跑 `run_local.bat --only zgdc`。

## 八、常见问题

**Q: 某个源突然变成空的 / 不存在了?**

不会变成空的。脚本有「保留旧版」逻辑: 抓不到就保留上一次的成品, 绝不覆盖成空 feed。
你最多看到它停留在旧内容上, 而不是一片空白。要看是哪个源出问题, 去 Actions 日志里搜 `[失败]`。

**Q: 站点改版了怎么办?**

会看到 `[失败] ... 页面结构变了` 之类的日志。那时需要按新结构调 `build.py` 里对应的解析函数。
`--dry-run` 参数可以只抓取、只打印、不写文件, 适合边改边试:

```
run_local.bat --dry-run
```

**Q: 定时任务会不会自己停掉?**

GitHub 会在仓库连续 60 天没有任何活动时暂停定时任务。因为本工作流每次有更新都会提交,
仓库一直有活动, 一般不会触发。万一被暂停, 去 Actions 页面点一次 Enable 就好。

**Q: 能不能用私有仓库?**

可以建私有仓库, 但免费账号的 GitHub Pages 不支持私有仓库, 你就拿不到给 Inoreader 用的网址了。
想保持私密又免费的话, 换个思路: 别用 Pages, 直接把 `docs/feeds/*.xml` 提交到仓库,
然后用 GitHub 的 raw 链接订阅。不过要注意 raw 链接有缓存, 更新时间会滞后, 体验差一些。

**Q: 为什么有些条目的时间只有日期没有时分?**

站点列表页本来只给了日期（南方电网、北极星都是这样）, 脚本就照实填。
这些条目在同一天内会按站点自己的排序展示。

**Q: 点开北极星的文章为什么偶尔弹验证码?**

北极星的文章页挂了阿里云 WAF。用正常浏览器打开一般会自动通过, 偶尔会弹一次滑块。
这是对方站点的策略, 不是订阅源坏了。

**Q: 知网那两个源, 为什么文章链接看起来很长、还带一串乱码?**

知网给的文章链接里带一个一次性的访问令牌 (`v=` 后面那一串), 每次请求都不一样。
如果不处理, 后果是: 同一篇文章每 2 小时就被当成一篇全新文章推给你, 你会在 Inoreader 里
被同样 20 篇论文反复刷屏。所以脚本做了两件事:

- GUID 用「标题 + 时间」算稳定哈希, Inoreader 才能认出这是同一篇文章;
- 链接沿用第一次抓到的那条, 不做替换, 这样文件不会每轮都变。

副作用是这条链接是第一次抓到时生成的。CNKI 自己的 RSS 就是给阅读器异步消费的,
所以令牌的有效期足够长; 万一遇到某条打不开, 用标题在知网搜一下就能找到原文。

## 九、文件说明

| 文件 | 作用 |
| --- | --- |
| `sources.py` | 源清单。增删源改这里 |
| `build.py` | 抓取和生成逻辑, 纯标准库, 零依赖 |
| `run_local.bat` | 本地手动跑一次。故意写成纯英文的批处理, 中文说明由 Python 输出 |
| `push-to-github.bat` | 一键初始化并推送到 GitHub。同样是纯英文批处理 |
| `next-steps.zh.txt` | 推送成功后要做的三件网页操作, 由上面那个脚本自动显示 |
| `.gitattributes` | 钉死换行符, 免得 Windows 和 Linux 上生成的文件互相打架 |
| `.github/workflows/update-feeds.yml` | 定时任务定义 |
| `docs/` | 生成结果, 也是 GitHub Pages 的根目录 |

`docs/` 里的东西都是自动生成的, 不用手改, 改了下一次运行会被覆盖。

顺带一句: 那两个 `.bat` 之所以坚持写英文, 是因为批处理文件里的中文会让 cmd.exe 在
非 UTF-8 代码页下解析错乱, 甚至把半行文字当成命令去执行。中文提示交给 Python 和这个
文档来显示就稳得多。
